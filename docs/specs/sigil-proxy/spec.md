# Sigil Proxy 요구사항

상태: 구현 준비 초안 · 2026-09-27

MUST는 해당 단계 출시 조건이다. P1은 관찰 MVP, P2는 정책 통제,
P3는 인간 승인·연결 확장이다. 미래 단계 요구사항은 P1 완료를 막지 않는다.

## 목적과 범위

운영자가 다른 MCP 서버를 등록하고 클라이언트를 proxy로 연결하면,
manager에서 누가 어떤 도구를 호출했고 어떤 응답 상태를 받았는지 확인한다.

MCP 통신 관찰은 서버 내부 행동이나 외부 서비스의 실제 변경을 증명하지 않는다.
직접 접속, shell/API 호출, 사용자 PC의 stdio 연결은 자동으로 포착하지 않는다.
프롬프트 인젝션 완전 차단, 범용 네트워크 proxy, 새 관리 UI 앱은 범위 밖이다.

## 요구사항

| ID | 단계 | 필수 동작 |
|---|---|---|
| PX-001 | P1 | 독립 바이너리·설정·서비스로 실행하며 개인 설치에 기본 활성화하지 않는다. |
| PX-002 | P1 | 등록한 원격 Streamable HTTP MCP를 서버별 고정 라우트로 중계한다. 요청자가 임의 upstream URL을 지정할 수 없다. |
| PX-003 | P1 | 검증한 프로토콜 버전만 지원한다. 버전별 메시지 방향·메타데이터·취소·스트리밍 의미를 보존하고 지원하지 않는 조합을 명시적으로 거절한다. |
| PX-004 | P1 | tools/resources/prompts와 알림 등 지원 범위를 capability 표로 공개한다. 지원하지 않는 기능을 광고하거나 조용히 버리지 않는다. |
| PX-005 | P1 | 서버 정보와 도구 목록을 수집하고 도구 추가·삭제·정의 변경을 기록한다. 첫 관찰은 baseline이며 승인이 아니다. |
| PX-006 | P1 | 요청·판단·응답을 호출 ID로 연결한다. 성공, 도구 오류, 프로토콜 오류, 취소 요청, 시간 초과, 결과 불명을 구분한다. |
| PX-007 | P1 | 실행 주체·권한 소유자·검증 근거를 분리한다. 미확인 값은 unknown이며 자기신고를 인증된 사실로 승격하지 않는다. |
| PX-008 | P1 | 클라이언트 인증과 등록 라우트 접근 제한을 관찰 모드에서도 적용한다. 연결·호출·세션/스트림을 인증 주체별로 격리한다. |
| PX-009 | P1 | downstream/upstream/control-plane 자격증명을 분리한다. 비밀값을 API·로그·이벤트·manager에 반환하지 않는다. |
| PX-010 | P1 | 인자·응답 원문을 기본 저장하지 않는다. 기본 이벤트에는 허용된 메타데이터만 포함한다. |
| PX-011 | P1 | 로컬 spool, 재전송, 중앙 중복 제거, 재시작 복구와 감사 공백 표시를 제공한다. 도구 실행을 재시도해서 감사 전송을 복구하지 않는다. |
| PX-012 | P1 | server를 통해 등록·설정 배포·상태·이벤트 조회를 제공하고 manager에 관찰 화면을 추가한다. |
| PX-013 | P1 | 요청 크기·응답 처리량·동시성·시간·spool 용량을 제한하고 backpressure와 정상 종료를 구현한다. |
| PX-014 | P1 | 인증 실패, 잘못된 Origin, SSRF·DNS 재바인딩·redirect 우회·다른 주체의 세션 재사용을 거절한다. 사설망 목적지는 명시적 관리 설정으로만 허용한다. |
| PX-015 | P1 | 도구 호출을 자동 재실행하지 않는다. 응답 유실은 결과 불명이며 미실행이나 성공으로 추정하지 않는다. |
| PX-016 | P1 | 설정 버전, 마지막 연결 시각, 수집 공백, 중앙 연결 단절, 적용/원하는 버전 차이를 표시한다. |
| PX-017 | P2 | observe/enforce와 allow/deny/require_approval 판단을 구분한다. observe에서는 would-deny만 기록하고 실제 도구 정책 차단은 하지 않는다. PX-008/014는 항상 적용한다. |
| PX-018 | P2 | 서버·도구·인증 주체·위임·구조화 인자로 호출 시점에 정책을 평가한다. 도구 목록 필터링만으로 통제를 대신하지 않는다. |
| PX-019 | P2 | 만료·위조·알 수 없는 정책을 허용으로 해석하지 않는다. 유효한 정책이 없는 enforce 경로는 차단한다. |
| PX-020 | P2 | 위임의 범위·만료·폐기를 검사하고 정책 버전과 판단 이유를 기록한다. readOnlyHint를 안전성 증명으로 쓰지 않는다. |
| PX-021 | P3 | 승인을 주체·권한 참조·서버·도구·정규화 인자 해시·정의 해시·정책 버전·만료에 결합한다. 변경·재사용·중복 소비를 거절한다. |
| PX-022 | P3 | 승인·거절·취소·만료·소비를 감사하고 전송 직전에 정책·위임·승인 유효성을 다시 검사한다. |
| PX-023 | P3 | manager 승인자 권한을 에이전트 자격증명과 분리한다. 인간 승인된 에이전트도 non-human 실행 주체로 유지한다. |
| PX-024 | P3 | 사용자별 OAuth 및 proxy 호스트 stdio 실행은 별도 호환성·보안 검증 후 추가한다. 원격 PC stdio bridge는 별도 스펙으로 다룬다. |

## 인수 시나리오

| ID | 연결 요구사항 | Given / When / Then |
|---|---|---|
| AC-01 | 001–004,012 | 등록된 시험 MCP와 인증 클라이언트가 있을 때 조회 도구를 호출하면 정상 응답과 manager 기록이 같은 호출 ID로 확인된다. |
| AC-02 | 005 | 완전한 도구 목록 관찰 후 도구가 추가·변경·삭제되면 차이가 표시된다. 페이지 누락·접근 권한 차이·오류를 삭제로 오인하지 않는다. |
| AC-03 | 006,015 | upstream이 작업을 받은 뒤 응답 연결이 끊기면 결과 불명으로 남고 proxy가 재실행하지 않는다. |
| AC-04 | 007–009 | 에이전트가 human=true를 보내거나 타 주체 세션/라우트를 사용하면 인간 인증으로 인정하지 않고 무권한 접근을 거절한다. |
| AC-05 | 009,010 | 인자·응답·오류에 canary 비밀값을 넣어도 기본 로그·spool·server API·manager에 원문이 없다. |
| AC-06 | 011,016 | server 단절 중 호출을 기록하고 재연결하면 이벤트를 재전송한다. 중복은 합쳐지고 수집 공백은 숨겨지지 않는다. |
| AC-07 | 003,013 | SSE, 취소, 버전별 세션 또는 요청 메타데이터, 큰 응답과 동시 호출에서 의미가 보존되고 자원 사용이 설정 한도를 지킨다. |
| AC-08 | 002,014 | localhost/metadata 주소·IPv6·redirect·DNS 변경으로 허용 목적지를 우회하거나 Origin을 위조해도 접근 정책이 유지된다. 요청 URL·헤더·본문으로 upstream을 지정해도 등록된 고정 라우트의 upstream만 사용한다. |
| AC-09 | 017–020 | 같은 금지 도구를 observe와 enforce에서 호출하면 각각 전달+would-deny, 미전달+deny가 된다. 만료 정책에서는 enforce가 전달하지 않는다. |
| AC-10 | 018,020 | 목록에서 감춘 도구 직접 호출과 폐기된 위임 사용은 실행 전에 차단된다. |
| AC-11 | 021–023 | 승인한 요청의 인자·주체·도구 정의가 바뀌거나 두 번 소비되면 거절한다. 동시 소비에서도 upstream 전달은 최대 한 번이다. |
| AC-12 | 008,011,013,016,019 | 재시작·디스크 가득 참·유효 정책 만료·중앙 단절·원격 설정 TTL 만료를 주입하면 설계의 장애 표와 상태 표시가 일치한다. |
| AC-13 | 012,023 | 조회자나 에이전트가 설정 변경/승인 API를 호출하면 거절되고, 권한 있는 작업도 감사 기록을 남긴다. |
| AC-14 | 001 | 3개 OS의 개인 설치 경로(install.sh, install.ps1)와 Rocky rpm을 기본 옵션으로 새로 설치했을 때 설치 결과와 서비스·listen 상태를 확인하면, proxy 바이너리·서비스·설정이 기본 활성화되지 않고 listener도 없다. rpm의 proxy service unit은 자동 enable/start되지 않으며 proxy는 기존 sigil과 별도의 설정·state_dir·unit을 쓴다. 명시적 `--config` 없이는 proxy가 기동하지 않는다. 설치 전후의 기존 sigil 동작(`sigil doctor`, `sigil scan` 출력)이 같고, proxy를 중지·제거해도 변하지 않는다. |
| AC-15 | 003,004 | [support-matrix.md](support-matrix.md)의 각 행을 §5 oracle대로 시험하면, 지원 행은 표대로 동작하고 미지원 행은 행마다 정해진 응답(modern 요청은 400+빈 body, `tasks/*`는 -32601, upstream tasks capability·upstream 2025-06-18 응답은 initialize의 -32603 route 거절)과 감사 기록으로 거절된다. client가 2025-06-18을 제시한 initialize는 그대로 전달하고 upstream 응답 revision으로 판단한다. 미지원 기능이 capability로 광고되거나 조용히 버려지지 않는다. 표에 undecided 행이 남아 있으면 통과하지 않는다. |

## 단계별 완료 정의

- P1: PX-001–016 및 AC-01–08, AC-12의 P1 부분, AC-13의 P1 부분, AC-14, AC-15 통과.
  최소 실제 클라이언트 1종 + 시험 MCP 1종의 end-to-end 증거와
  [지원 표](support-matrix.md)(undecided 행 없음)가 필요하다.
  - AC-12의 P1 부분: 재시작·디스크 가득 참·중앙 단절 주입 시 PX-011(재시작 복구),
    PX-013(spool 용량·backpressure·정상 종료)과 PX-016(설정 버전 차이·수집 공백·연결 단절 표시)이
    설계의 장애 표와 일치한다. 원격 설정 TTL이 만료되면 새 호출을 전달하지 않는다(PX-008/016,
    [contracts](contracts/README.md) "Bootstrap 구성 후보"). 이는 P2 정책 만료와 다르다.
    "유효 정책 만료" 주입(PX-019)은 P2 부분이며 P1 완료 조건이 아니다.
  - AC-13의 P1 부분: 조회자·에이전트의 설정 변경 API 거절과 권한 있는 관리 작업의 감사 기록(PX-012).
    승인 API(PX-023)는 P3 부분이다.
- P2: PX-017–020 및 AC-09/10, AC-12의 정책 부분(유효 정책 만료, PX-019) 통과. 통제 범위와 우회 가능성을 배포 문서에 표시한다.
- P3: PX-021–023 및 AC-11/13(승인 API 부분) 통과 후 승인 활성화. PX-024의 각 adapter는 별도 출시 단위다.
- 성능 수치는 P0에서 시험 환경·목표와 함께 고정하고 P1 결과를 기록한다. 측정 전 처리량 보장은 하지 않는다.
