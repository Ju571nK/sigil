# Sigil Proxy — spec-driven implementation

작성: 2026-09-27 · 상태: 구현 준비 초안 · 기준 커밋: `24eddb2`

## 확정한 제품 방향

`sigil-proxy`는 `sigil-server`처럼 독립적으로 실행·배포하는 선택형 서비스다.
백엔드는 이 저장소의 `crates/sigil-proxy`에 추가한다. 새 저장소나 Git submodule은
만들지 않는다. 모든 관리 화면은 기존 `sigil-manager`에 추가한다.

다른 MCP 서버의 호출과 응답을 관찰하는 것이 첫 목표다. 실행 주체, 권한 소유자,
위임, 인간 승인을 분리해 기록하고 정책 통제와 승인 기능을 단계적으로 확장한다.
현재 이 문서는 계획이며 proxy 기능이 구현되었다는 의미가 아니다.

## Spec-driven 작업 규칙

- 코드 작업 전 해당 요구사항 ID와 인수 시나리오를 작업/PR에 연결한다.
- 스펙 변경이 필요하면 요구사항·설계·검증 항목을 먼저 또는 같은 PR에서 수정한다.
- 계약이 미확정인 기능은 연결된 결정 항목을 해결한 뒤 구현한다. 독립 작업은 진행 가능하다.
- 구현 완료와 실기 검증 완료를 구분한다. 문서나 mock 통과만으로 제품 호환성을 선언하지 않는다.
- 단계 완료 시 PR/커밋, 테스트 결과, 클라이언트·서버 버전, 잔여 제한을 plan에 기록한다.
- manager 작업은 해당 저장소의 지침과 실제 인증·API 구조를 먼저 확인한다.
  이 문서는 manager 코드가 조사 또는 변경되었다고 주장하지 않는다.
- 기존 hook enforcement와 제품별 compatibility gate는 유지한다.
