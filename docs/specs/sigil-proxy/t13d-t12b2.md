# T-13d / T-12b2 implementation contract and acceptance

AC-03/04/05/06/07/08/12/15. Defines completion of these two implementation tasks;
it does not declare P1 release, hardware compatibility, policy enforcement or manager integration complete.

Read with `decisions.md`, `contracts/README.md`, `contracts/control-plane.md` §5.3,
and [dated compatibility evidence](../../research/sigil-proxy-t12b2-compatibility-2026-10-24.md).

## Narrow implementation choices

These fill transport details without changing the decided support scope:

- Authenticate and authorize the route before inspecting session/protocol details.
  A non-initialize POST without a required proxy session gets HTTP 400 with an empty body;
  an unknown, foreign-principal, foreign-route or invalidated session gets the same fixed 404.
  These transport/session rejections do not create an invocation. Authenticated B1 modern markers
  (including pre-initialize server/discover) retain their existing interception/audit before session lookup. A valid-session request
  rejected for its protocol header follows the existing start/completion audit contract.
- Issue a cryptographically random proxy session even if upstream is stateless. Do not forward
  this id upstream. Preserve the upstream session header privately when present; otherwise omit it.
  DELETE of a stateless-upstream proxy session invalidates locally and returns 204 without an upstream request.
- An upstream 404 on a bound POST (including a proxy session for a stateless upstream) invalidates
  the binding, returns an empty 404 downstream,
  and completes the dispatched invocation as unknown/sent (no invented reason).
- A downstream disconnect after dispatch never synthesizes an upstream cancellation or a
  cancel_requested event (pinned legacy semantics; do not adopt the modern close-is-cancel rule).
- GET remains authenticated fixed 405 with no upstream contact or invocation. P1 has no stream
  resumption; `Last-Event-ID` remains stripped on POST, as in the existing header policy.
- Initialize carrying any `Mcp-Session-Id` is rejected after auth and before session lookup with
  HTTP 400 empty body, no invocation and no upstream contact, identically for own/foreign/unknown ids. A refused/unreadable
  upstream initialize never establishes a downstream session. Capture any upstream session header
  before buffering so best-effort bounded DELETE cleanup can use it. Cleanup never retries a tool call.
- The fixed initialize runtime refusal is HTTP 200 application/json, JSON-RPC -32603,
  message `Internal error`, matching initialize id, no data or untrusted text.
- Post-initialize missing/known-legacy mismatched version header: HTTP 400 empty body,
  protocol_error/not_sent with no new reason constant. Modern markers retain the existing B1 vocabulary.
- A session is bound to principal, route and the upstream/credential visibility binding that created it.
  A config repoint must not attach an old upstream session to a different endpoint/credential scope.
  Current authentication and config TTL still apply per request. In-flight calls keep their immutable context.
- A new initialize on an already unsupported binding is refused locally before upstream contact,
  with the same fixed -32603 and protocol_error/not_sent completion, reason omitted. Runtime
  unsupported state resets only on binding change/restart, not a routine revision refresh.
- Session capacity refusal is fixed HTTP 429 `too_many_sessions`, no invocation and no upstream contact.
- Conservative transport failure mapping is unknown with the actual delivery state; never fabricate
  success, denial or non-execution from an upstream HTTP error.
- Apply existing total/per-principal/idle limits, including pending initializes; do not evict an active
  session as idle. End inventory chains and early-cancel state when a session ends. Never persist raw session ids.

## T-13d acceptance

1. Each audited request has a fresh invocation id. Started is durably appended locally before the single
   upstream dispatch; full/unavailable spool or producer capacity refuses dispatch with fixed 503.
2. Start provenance comes from the same immutable applied route/principal snapshot: upstream id,
   actual route revision, actor mapping (never client self-report), and validated negotiated protocol.
   Initialize and unnegotiated/B1 starts remain protocol unknown. Tool name resolves only in local scoped
   inventory; ordinary events contain a ref or the fixed unavailable object, never raw names/arguments/results.
3. Forwarded, locally refused, canceled and interrupted requests use the existing closed outcome/delivery/reason
   matrix. Cancel is nonterminal. No tool execution retry, fabricated success or synthetic restart completion.
4. Completion/cancel storage work is bounded and off Tokio I/O workers; failures are visible through existing
   local_record_failed/gap/degraded mechanisms. Drain the producer after relay drain and before stopping tasks.
   Grace expiry stops relay connections, then every pending start commit and producer cleanup retains an owner
   until accounting and the accepted-or-counted gap handover finish. A permanently blocked storage operation
   keeps lifecycle `Stopping`; it must not publish `Stopped` with cleanup only in detached memory.
   Storage persistence failures remain explicitly degraded; successful disk writes cannot be promised on failed storage.
5. A real proxy-to-server test observes start/completion (and cancel where applicable), offline spool replay
   and de-duplication. A spool refusal oracle proves upstream call count zero. Canary raw content is absent
   from spool events, logs and ordinary query responses.

## T-12b2 acceptance

1. JSON and SSE initialize are buffered only until the complete matching response; supported held bytes
   retain order and content, then the remainder streams. Mismatched ids, bounds, encodings and timeouts fail safely.
2. Reject unsupported revision, tasks and resources.subscribe capabilities without advertising them;
   apply the existing fixed reason/route-health vocabulary and upstream session cleanup. A task handle on an
   otherwise supported route retains the existing relay/audit/degraded contract.
3. Proxy-issued session ids use at least 128 CSPRNG bits encoded as visible ASCII (0x21–0x7E),
   never reveal upstream ids; same request ids in distinct sessions/principals/routes
   cannot collide or cancel one another. Missing, duplicate, foreign and expired headers have fixed rejection oracles.
4. DELETE forwards once for stateful upstream: 2xx/404 invalidate; 405/other error preserve the session.
   Test stateless DELETE, upstream POST 404, idle expiry, capacity, config changes, and active-call lifetime.
5. Post-initialize protocol checks cover missing, duplicate, legacy mismatch and modern markers, always after auth.
   GET stays fixed405. Notifications and client responses are forwarded without fabricated invocation events.
6. Existing relay byte preservation, SSRF/Origin/credential stripping, cancellation ordering, limits,
   registry conflict recovery and Windows fallback remain verified. No bypass disables session checks in production.

## Evidence and release boundary

Record implementation, independent review, targeted integration tests, workspace gates and CI separately in
`execution.md`. Real client versions found in the compatibility research differ from old measurements;
keep their proxy-path/hardware status unverified until a separate explicit probe is run. This patch must not
silently promote the prior Claude/Codex measurements into current-version compatibility claims.

Open P1 requirements outside these two runtime tasks: M2/m3 registration and health-check
unsupported verdicts remain decided requirements that are not delivered here; proactive upstream
initialize probes are not introduced. Only runtime initialize evidence feeds route health.
Idle/shutdown local session expiry sends no unsolicited upstream DELETE. No P1 release or probe
coverage is claimed until these outstanding requirements and real-client verification are met.
