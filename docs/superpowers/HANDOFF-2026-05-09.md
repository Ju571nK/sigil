## 2. 핵심 framing 결정 (재논의 금지)

| 결정 | 의미 |
|---|---|
| **Ride-along** | EDR + MDM + SIEM 가 이미 운영된다고 가정. ANDEDA 는 그 위에 얹는 thin tenant. EDR 흉내 X. |
| **탐지-only** | 차단/격리/롤백 없음. 이벤트 발신만. enforcement 는 EDR 영역. |
| **타겟 OS** | macOS, Windows. Linux 는 빌드만 검증 (Phase 2+). |
| **Phase 1 = 파일 워처** | 네트워크 프록시(Phase 2), 프로세스 추적(Phase 3) 은 후순위. |
| **메타데이터-only 이벤트** | path + before/after blake3 hash. 파일 내용은 머신을 안 떠남. |
| **출력 = 로컬 JSONL** | SIEM 에이전트(Splunk Forwarder, Datadog Agent, Filebeat 등)가 픽업. 데몬은 HTTP 안 씀. |
| **다중 사용자** | 전 사용자 enumeration. macOS `/Users/*`, Windows `C:\Users\*`. 시스템/관리 계정 제외. |
| **Renamed = 단일 이벤트** | from/to 필드 한 줄. 200ms pairing window. |
| **Event-first commit** | JSONL 먼저 쓰고 state.db 그 다음. SIEM 측 idempotent dedup 룰로 중복 흡수. |
| **변조 방지 = 0** | 자기 방어 없음. heartbeat 만 가시성 시그널. |

## 4. 어디서 멈췄는가

writing-plans 스킬의 마지막 단계 = **Execution Handoff**.

> Plan complete and saved to `...`. Two execution options:
> 1. Subagent-Driven (recommended) — fresh subagent per task
> 2. Inline Execution — batched with checkpoints
>
> Which approach?

이 질문에 대한 답을 받기 직전. 사용자가 "다른 세션에서 진행" 을 선택해서 핸드오프 작성.

## 5. 다음 세션이 해야 할 일

### 즉시 (첫 메시지)

다음 세션의 사용자 입력으로 다음 둘 중 하나를 추천:

**옵션 A — Subagent-Driven 으로 바로 실행 시작:**
```
docs/superpowers/plans/2026-05-09-andeda-phase1.md 의 ANDEDA Phase 1 플랜을
superpowers:subagent-driven-development 스킬로 실행해줘. Task 1 부터 시작.
```

**옵션 B — Inline 실행:**
```
docs/superpowers/plans/2026-05-09-andeda-phase1.md 의 ANDEDA Phase 1 플랜을
superpowers:executing-plans 스킬로 batch 실행해줘. 5 task 마다 체크포인트.
```

### 실행 중

- 매 task 의 5 step (write test → run → impl → run → commit) 을 빠짐없이 수행
- 각 task 끝에서 `cargo test` 통과 확인
- 각 task 가 자체 commit 생성

### 알아둘 함정 / 예상 실패 지점

| 단계 | 가능한 실패 | 대응 |
|---|---|---|
| Task 1 commit | git config user.email 미설정 | `git config --local user.email/name` 우선 처리. 사용자가 직접 설정 권한. |
| Task 22 (notify 통합) | macOS FSEvents 가 tempdir 권한으로 이벤트 안 올 때 | 200~500ms sleep 후 retry. 실패하면 평소 이슈, 사용자에게 보고. |
| Task 28 (macOS) | system_profiler shell-out 이 CI 에서 느림 | 타임아웃 60s 적용. Hardware UUID 못 읽으면 hostname 으로 폴백 (이미 구현됨). |
| Task 29 (Windows) | `reg query` parsing — 로케일에 따라 출력 포맷 다름 | 영문 머신 가정. 다른 로케일이면 Path 매칭 실패할 수 있음. |
| Task 33 (runtime) | tokio Handle::current() 가 spawn_blocking 콜백 안에서 panic | watcher 콜백은 동기 컨텍스트. handle.spawn 으로 우회 (이미 구현됨). |
| Task 35-41 (통합 테스트) | TestAgent 가 종료 안 되어 다음 테스트 hang | 각 테스트 끝에서 `agent.join.abort()` 명시 필요. |
| Task 42 (proptest) | 256 cases × 6 properties 가 release 모드 30s 이상 걸림 | proptest 환경변수 `PROPTEST_CASES=64` 로 CI 단축 가능. |
| Task 43 (CI) | macos-14 가 GitHub Actions runner 에 fsync 비용 큼 | 잘못된 fsync 빈도면 테스트가 flake. interval 조정 검토. |
